# Инвентаризация ASCII-схем и план инженерных досок

В редакции v6 — 27 блоков в моноширинном формате. Для сохранения ритма статьи они объединяются в 18 иллюстраций: каждая заменяет один самостоятельный смысловой фрагмент или связанный контраст.

| № | ASCII-блоки | Рисунок | Что показываем |
|---:|---|---|---|
| 01 | 1–2 | От проблемы к решению: раньше и теперь | Два вертикальных маршрута: долгий одиночный поиск против инженерного цикла «инженер + AI». |
| 02 | 3–4 | Ответственность инженера | Красный «инженер → AI → готово» и зелёный замкнутый цикл постановки задачи, работы агентов, проверки и решения инженером. |
| 03 | 5–7 | Проверенная гипотеза | Линия «идея → исследование → архитектура → PoC → тест → измерение → GO/NO-GO»; рядом контраст с бесконечными обсуждениями. |
| 04 | 8 | AI-native product development loop | Кольцо «рынок → проблема → гипотеза → исследование → архитектура → PoC → проверка → измерение → продукт → рынок». |
| 05 | 9 | Архитектурный trade-off | Один вариант архитектуры расходится на безопасность, стоимость и сложность, затем сходится в решение. |
| 06 | 10–11 | Смена роли в программировании | Слева инженер пишет каждую строку; справа инженер задаёт ограничения, агент реализует и тестирует, CI возвращает результат. |
| 07 | 12 | Экспериментальный цикл агента | «Read code → change → build → run → test → measure → analyze → fix → run again». |
| 08 | 13 | Репозиторий как память проекта | Код, документация и тесты сходятся в `PROJECT STATE`; применяется уже сохранённая доска. |
| 09 | 14 | Накопительная R&D-память | Продукты, технологии и рынок питают базу знаний, поверх которой работают агенты. |
| 10 | 15–16 | Конкурентная воронка | Слева мало идей и один результат; справа много гипотез, AI research, PoC и несколько кандидатов. |
| 11 | 17 | Стоимость попытки и скорость обучения | Дешёвый эксперимент ведёт к большему числу попыток, быстрому обучению и лучшему продукту; уже сохранённая доска. |
| 12 | 18 | AI в наборе инженерных инструментов | Git, IDE, debugger, compiler, Wireshark, JTAG и AI — один набор, не отдельная магия. |
| 13 | 19 | AI-ready repository | Структура репозитория: `AGENTS.md`, docs, backlog, tests, benchmarks, src. |
| 14 | 20 | Протокол AI research | «Question → research → known/unknown → options → risks → experiment → decision». |
| 15 | 21 | Параллельные агенты | Инженер координирует research, security и prototype-агентов, затем принимает решение; уже сохранённая доска. |
| 16 | 22 | Конкурентный радар | Рынок → сигналы → AI-анализ → возможности → гипотезы → PoC → продукт → рынок. |
| 17 | 23–24 | Новая роль инженера | От «знает, пишет, отлаживает» к «понимает, решает, проверяет, управляет агентами». |
| 18 | 25–27 | Скорость обучения как стратегия | Быстрее увидеть → понять → проверить → ошибиться → исправить → создать → выйти на рынок; внизу формула R&D-скорости и набор рабочих задач. |

Все иллюстрации должны быть широкими PNG в едином стиле: тёплая белая инженерная доска, тонкий чёрный маркер, рукописные синие заголовки, красные предупреждения и зелёные подтверждения. Текст на картинках минимален, а смысл дополнительно сохраняется в подписи под каждой иллюстрацией.
